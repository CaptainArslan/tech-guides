Deploy Laravel on a VPS

Every command to take a bare Ubuntu server — on AWS EC2, a DigitalOcean Droplet, or anywhere else you can SSH in — and turn it into a production Laravel host: Nginx, PHP-FPM, Composer, MySQL, phpMyAdmin, a GitHub SSH connection, Supervisor queue workers, and the Laravel scheduler.

Everywhere you see laravel-app, your-username, your-domain.com or a password placeholder, swap in your own values.

01

Provision & harden the server

Spin up an Ubuntu 22.04 LTS server — an AWS EC2 instance or a DigitalOcean Droplet both work identically from here on. Add your SSH public key at creation time so you never need a password.

shell · from your local machine
# AWS EC2 default user is "ubuntu"; DigitalOcean is usually "root"
ssh ubuntu@your_server_ip          # AWS
ssh root@your_server_ip            # DigitalOcean

Update the box and create a non-root sudo user to work from — never deploy as root day-to-day.

shell · on the server
sudo apt update && sudo apt upgrade -y

sudo adduser deploy
sudo usermod -aG sudo deploy

# copy your SSH key over to the new user
sudo rsync --archive --chown=deploy:deploy ~/.ssh /home/deploy

# log out and back in as the new user from now on
exit
ssh deploy@your_server_ip

Lock down the firewall and set the timezone.

shell
sudo ufw allow OpenSSH
sudo ufw allow 'Nginx Full'
sudo ufw enable
sudo ufw status

sudo timedatectl set-timezone UTC
timedatectl          # verify
AWS vs DigitalOcean: on AWS you must also open ports 22, 80 and 443 inbound on the instance's Security Group in the console — ufw alone won't let traffic through. On DigitalOcean, either use a Cloud Firewall from the dashboard or rely on ufw on the Droplet itself; both need to agree.
Optional but recommended: disable root SSH login and password authentication once your deploy user and key both work — edit /etc/ssh/sshd_config, set PermitRootLogin no and PasswordAuthentication no, then sudo systemctl restart ssh.

Install fail2ban to automatically block IPs that fail SSH authentication repeatedly — a cheap, effective guard against brute-force attacks.

shell
sudo apt install -y fail2ban
sudo systemctl enable fail2ban --now
sudo systemctl status fail2ban

# verify it's watching SSH
sudo fail2ban-client status sshd
02

Install Nginx

shell
sudo apt install -y nginx
sudo systemctl enable nginx --now
sudo systemctl status nginx

# confirm the default page is served
curl -I http://localhost

Visit http://your_server_ip in a browser — you should see the default "Welcome to nginx!" page.

03

Install PHP & PHP-FPM

Ubuntu's default repos lag behind, so add the ondrej/php PPA to get current PHP versions and every extension Laravel needs.

shell
sudo apt install -y software-properties-common
sudo add-apt-repository ppa:ondrej/php -y
sudo apt update

sudo apt install -y php8.4-fpm php8.4-cli php8.4-common \
  php8.4-mysql php8.4-xml php8.4-mbstring php8.4-curl \
  php8.4-zip php8.4-bcmath php8.4-gd php8.4-intl \
  php8.4-opcache php8.4-readline

php -v
sudo systemctl enable php8.4-fpm --now
sudo systemctl status php8.4-fpm
Match the PHP version to your Laravel release: Laravel 12 / 11 need PHP 8.2+, Laravel 10 needs 8.1+. Swap every php8.4 above (and later in this guide) for the version your composer.json requires.
04

Install Composer

shell
cd ~
curl -sS https://getcomposer.org/installer -o composer-setup.php

# verify the installer against Composer's published signature
HASH=$(curl -sS https://composer.github.io/installer.sig)
php -r "if (hash_file('sha384', 'composer-setup.php') === '$HASH') { echo 'Installer verified'.PHP_EOL; } else { echo 'Installer corrupt'.PHP_EOL; unlink('composer-setup.php'); }"

sudo php composer-setup.php --install-dir=/usr/local/bin --filename=composer
rm composer-setup.php

composer --version
05

Install & secure MySQL

Install & start

shell
sudo apt install -y mysql-server
sudo systemctl enable mysql --now
sudo systemctl status mysql

Run the secure installation wizard — it will walk you through setting a root password, removing anonymous users, disallowing remote root login, and dropping the test database. Answer Yes to every prompt.

shell
sudo mysql_secure_installation
Ubuntu / MySQL 8 note: on a fresh install the root account uses auth_socket (no password, only reachable via sudo mysql). The wizard will ask "Switch to unix_socket authentication?" — answer No to keep password auth available — then "Change the root password?" — answer Yes and set a strong password. After this, both sudo mysql and mysql -u root -p will work.

Log in as root with the password you just set to confirm it works:

shell
mysql -u root -p          # enter the root password when prompted

Inside the MySQL shell — create the app database, a dedicated user, and grant that user full privileges on the new database. Never point .env at root.

sql
CREATE DATABASE laravel_app CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

CREATE USER 'laravel_user'@'localhost' IDENTIFIED BY 'change-this-strong-password';

GRANT ALL PRIVILEGES ON laravel_app.* TO 'laravel_user'@'localhost';

FLUSH PRIVILEGES;

SHOW GRANTS FOR 'laravel_user'@'localhost';          # verify

EXIT;

Verify the app user can connect and see the database:

shell
mysql -u laravel_user -p laravel_app          # enter laravel_user's password
sql
SHOW DATABASES;          # laravel_app must appear in the list
EXIT;
06

Install phpMyAdmin (optional)

The Debian/Ubuntu package auto-configures itself for Apache. Since we're running Nginx, install it, decline the Apache prompt, then wire it up manually.

shell
sudo apt install -y phpmyadmin
# when prompted "Web server to reconfigure automatically", press SPACE
# to deselect apache2 (leave nothing selected), then Tab → OK
# choose "Yes" to configure a database for phpmyadmin with dbconfig-common

Point a dedicated Nginx server block at it, on its own subdomain so it's never mixed in with the app.

/etc/nginx/sites-available/phpmyadmin
server {
    listen 80;
    server_name pma.your-domain.com;
    root /usr/share/phpmyadmin;
    index index.php;

    location / {
        try_files $uri $uri/ =404;
    }

    location ~ \.php$ {
        include snippets/fastcgi-php.conf;
        fastcgi_pass unix:/run/php/php8.4-fpm.sock;
    }

    location ~ /\.ht {
        deny all;
    }
}
shell
sudo ln -s /etc/nginx/sites-available/phpmyadmin /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx
Treat phpMyAdmin as a liability if it's public. At minimum: put it behind HTTPS (step 11), restrict the server block to your office/home IP with allow/deny, or skip exposing it entirely and reach it over an SSH tunnel instead: ssh -L 8000:localhost:80 deploy@your_server_ip, then browse to localhost:8000 with the Host header set to pma.your-domain.com (or just add it to your local /etc/hosts).
07

Connect the server to GitHub over SSH

shell · as the deploy user
ssh-keygen -t ed25519 -C "deploy@your-server"
# press Enter to accept the default path, set a passphrase or leave it empty

eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519

cat ~/.ssh/id_ed25519.pub
# copy the printed key

On GitHub: Settings → SSH and GPG keys → New SSH key for account-wide access, or, safer for a single production server, the repository's own Settings → Deploy keys for read-only access scoped to that one repo. Paste the public key you just copied.

shell
ssh -T git@github.com
# expect: "Hi your-username! You've successfully authenticated..."

09

Set permissions & run migrations

shell
sudo chown -R www-data:www-data /var/www/laravel-app
sudo find /var/www/laravel-app -type f -exec chmod 644 {} \;
sudo find /var/www/laravel-app -type d -exec chmod 755 {} \;

# storage/ and bootstrap/cache/ must stay writable by the web server
sudo chmod -R ug+rwx /var/www/laravel-app/storage /var/www/laravel-app/bootstrap/cache
shell
php artisan migrate --force
php artisan storage:link
php artisan optimize          # cache config, routes, views & events for production
Add your user to the www-data group (sudo usermod -aG www-data deploy, then log out/in) so you can still edit files as deploy without switching to root every time.
10

Configure Nginx for Laravel

shell
sudo nano /etc/nginx/sites-available/laravel-app

Paste the vhost below (full copy in the Reference section). The key points: root points at public/, not the project root, and every request that isn't a real file falls through to index.php.

laravel-app
server {
    listen 80;
    listen [::]:80;
    server_name your-domain.com www.your-domain.com;
    root /var/www/laravel-app/public;

    server_tokens off;

    add_header X-Frame-Options "SAMEORIGIN";
    add_header X-Content-Type-Options "nosniff";
    add_header X-XSS-Protection "1; mode=block";
    add_header Referrer-Policy "strict-origin-when-cross-origin";

    index index.php;
    charset utf-8;

    client_max_body_size 20M;

    gzip on;
    gzip_types text/plain text/css application/json application/javascript
               text/xml application/xml application/xml+rss text/javascript
               image/svg+xml;
    gzip_vary on;

    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }

    location = /favicon.ico { access_log off; log_not_found off; }
    location = /robots.txt  { access_log off; log_not_found off; }

    error_page 404 /index.php;

    location ~ \.php$ {
        fastcgi_pass unix:/run/php/php8.4-fpm.sock;
        fastcgi_param SCRIPT_FILENAME $realpath_root$fastcgi_script_name;
        include fastcgi_params;
        fastcgi_hide_header X-Powered-By;
    }

    location ~ /\.(?!well-known).* {
        deny all;
    }
}
shell
sudo ln -s /etc/nginx/sites-available/laravel-app /etc/nginx/sites-enabled/
sudo unlink /etc/nginx/sites-enabled/default   # optional, removes the placeholder site

sudo nginx -t
sudo systemctl reload nginx
11

Enable HTTPS with Let's Encrypt

Point your domain's DNS A record at the server's IP before running this — Certbot validates ownership over HTTP first.

shell
# install via snap — the method Certbot officially recommends
sudo snap install --classic certbot
sudo ln -sfn /snap/bin/certbot /usr/local/bin/certbot
certbot --version          # verify

sudo certbot --nginx -d your-domain.com -d www.your-domain.com
# follow the prompts; choose "redirect" to force HTTPS

# confirm auto-renewal works
sudo certbot renew --dry-run
systemctl list-timers | grep snap.certbot          # renewal timer must appear
12

Set up Supervisor for queue workers

If your app dispatches queued jobs (mail, notifications, imports), a worker needs to run continuously and restart on crash or deploy — that's Supervisor's job.

shell
sudo apt install -y supervisor
sudo nano /etc/supervisor/conf.d/laravel-worker.conf
laravel-worker.conf
[program:laravel-worker]
process_name=%(program_name)s_%(process_num)02d
command=php /var/www/laravel-app/artisan queue:work --sleep=3 --tries=3 --max-time=3600
autostart=true
autorestart=true
stopasgroup=true
killasgroup=true
user=www-data
numprocs=2
redirect_stderr=true
stdout_logfile=/var/www/laravel-app/storage/logs/worker.log
stopwaitsecs=3600
shell
sudo supervisorctl reread
sudo supervisorctl update
sudo supervisorctl start "laravel-worker:*"
sudo supervisorctl status
Using Redis for the queue? Install it with sudo apt install -y redis-server and set QUEUE_CONNECTION=redis in .env — everything else in this section stays the same.
13

Set up the Laravel scheduler

Laravel's scheduler needs exactly one cron entry, running as www-data so file ownership stays consistent, which calls schedule:run every minute — Laravel itself decides what actually needs to fire.

shell
sudo crontab -u www-data -e
crontab
* * * * * cd /var/www/laravel-app && php artisan schedule:run >> /dev/null 2>&1
shell
sudo crontab -u www-data -l          # verify it's saved
tail -f /var/www/laravel-app/storage/logs/laravel.log   # watch scheduled jobs run
14

Zero-downtime redeploy workflow

A small script wraps the routine "new code just landed on main" flow so it's the same three keystrokes every time.

shell
nano /var/www/laravel-app/deploy.sh
deploy.sh
#!/usr/bin/env bash
set -e

cd /var/www/laravel-app

php artisan down --retry=60

git pull origin main
composer install --no-dev --optimize-autoloader

php artisan migrate --force
php artisan optimize          # caches config, routes, views & events in one step

php artisan queue:restart          # signal workers to finish current job then reload new code
sudo supervisorctl restart "laravel-worker:*"

php artisan up
shell
chmod +x /var/www/laravel-app/deploy.sh
./deploy.sh
Never edit files directly on the server. Every change should go through git — commit locally, push, then run deploy.sh. If the server has local edits, git pull will conflict.

Artisan cheatsheet

CommandWhat it does
php artisan migrate --forceRun pending migrations in production without the confirmation prompt.
php artisan migrate:fresh --seedDrop all tables, re-migrate, and seed — staging/dev only, never production.
php artisan config:cacheCompile .env + config files into one cached file for speed.
php artisan config:clearRemove the config cache — run this if .env changes aren't taking effect.
php artisan route:cache / route:clearCache or clear the route table.
php artisan view:cache / view:clearPrecompile or clear Blade views.
php artisan queue:workProcess queued jobs (what Supervisor runs).
php artisan queue:restartSignal running workers to finish their current job and restart — run after every deploy that touches job classes.
php artisan schedule:listShow every scheduled task and when it next runs.
php artisan tinkerInteractive REPL against your app.
php artisan down / upPut the app into or out of maintenance mode.
php artisan storage:linkSymlink public/storage to storage/app/public.
php artisan optimizeCache config, routes, views and events in one command — run after every production deploy (replaces the three separate cache commands).
php artisan optimize:clearClear all caches at once — useful when debugging cache-related issues or before rebuilding.

Troubleshooting

SymptomLikely fix
502 Bad GatewayPHP-FPM isn't running, or the socket path in the Nginx vhost doesn't match /run/php/php8.4-fpm.sock for your installed PHP version. Check with sudo systemctl status php8.4-fpm and ls /run/php/.
403 Forbiddenroot in the vhost points at the project root instead of public/, or file permissions are too strict. Re-check step 10 and the chmod in step 09.
Blank white pageAPP_DEBUG is false so errors are hidden. Temporarily set it to true in .env, reload, check storage/logs/laravel.log, then set it back to false.
"Permission denied" writing to storage/Ownership drifted from www-data, usually after a fresh git pull or clone. Re-run the chown/chmod commands from step 09.
.env changes have no effectA stale config cache is in play. Run php artisan config:clear, then re-cache with php artisan config:cache if you use it.
Migrations fail on deployCheck DB_* values in .env match step 05 exactly, and that the MySQL user has privileges on that database (SHOW GRANTS FOR 'laravel_user'@'localhost';).
Queue jobs never runsupervisorctl status should show the worker as RUNNING. If you changed a job class, run php artisan queue:restart so workers reload the new code.
Scheduled tasks don't fireConfirm the cron entry exists for www-data specifically (sudo crontab -u www-data -l), not for root or your own user.
git pull conflicts on the serverSomeone edited a tracked file directly on the server. Never do that — use git stash or git checkout -- . to discard the local change, then pull again.
