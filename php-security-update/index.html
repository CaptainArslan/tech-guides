Patch PHP on Ubuntu —
Security Update Guide

How to apply PHP security patches on an Ubuntu server running Nginx or Apache. Update package lists, upgrade PHP in-place, restart the right services, and confirm the patch took effect — without downtime.

~10 min Ubuntu 20.04 / 22.04 / 24.04 5 steps patch immediately
00

Quick Reference — All Commands

ℹ

If you just need the commands, copy this block and run it on your server. Replace 8.3 with your PHP version (check with php -v). If you use Apache instead of Nginx, swap the last two commands — see Step 04 below.

bash — all-in-one patch 
# 1. Refresh package lists
sudo apt update

# 2. Upgrade PHP packages only (safe, targeted)
sudo apt install --only-upgrade 'php*'

# 3. Restart PHP-FPM (replace 8.3 with your version)
sudo systemctl restart php8.3-fpm

# 4. Reload Nginx
sudo systemctl reload nginx

# 5. Verify
php -v

01

Check Your Current PHP Version

Before patching, record your exact PHP version. You'll need it to restart the right php-fpm service in Step 04.

bash 
php -v

Expected output — the version string like PHP 8.3.x tells you which FPM service name to use:

output 
PHP 8.3.14 (cli) (built: Nov 19 2024 10:38:19) (NTS)
Copyright (c) The PHP Group
Zend Engine v4.3.14, Copyright (c) Zend Technologies
    with Zend OPcache v8.3.14, Copyright (c), by Zend Technologies
→

If you have multiple PHP versions installed, run update-alternatives --list php to see all of them. Each version has its own php-fpm service that must be restarted separately.

02

Update Package Lists

This does not install or change anything — it only tells APT to fetch the latest list of available packages and versions from Ubuntu's repositories. Without this, apt install wouldn't know a newer PHP version exists.

bash 
sudo apt update

If you use a PPA like ondrej/php for newer PHP releases, it's refreshed too. You'll see a line like Hit:N https://ppa.launchpadcontent.net/ondrej/php/ubuntu jammy InRelease in the output.

03

Upgrade PHP Packages

You have two options. Option A is safer and more targeted — it only upgrades PHP-related packages and won't touch anything else on your server. Option B upgrades everything, which is fine if you're comfortable with a full system update.

bash 
# Upgrade only PHP packages — won't touch other system packages
sudo apt install --only-upgrade 'php*'
# Full system upgrade — includes PHP and everything else
sudo apt upgrade
!

Note: Neither option upgrades between major PHP versions (e.g., 8.2 → 8.3). That requires switching repositories. These commands apply security patches within your current major.minor version.

04

Restart PHP-FPM and Your Web Server

The new PHP binary is on disk, but your running PHP-FPM process still has the old one loaded in memory. You must restart it — the patch does nothing until you do. Replace 8.3 with whatever version php -v showed you in Step 01.

bash — Nginx + PHP-FPM stack 
# Restart PHP-FPM (loads the new binary into memory)
sudo systemctl restart php8.3-fpm

# Reload Nginx to reconnect to the updated FPM socket
sudo systemctl reload nginx

If you use Apache with mod_php instead of PHP-FPM, restart Apache only — PHP is embedded in the Apache process:

bash — Apache + mod_php stack 
# Restart Apache (mod_php is embedded in Apache)
sudo systemctl restart apache2
→

systemctl restart briefly drops all PHP-FPM worker processes, while reload gracefully replaces them. For a production server with active traffic, you can use systemctl reload php8.3-fpm for zero-downtime — workers finish their current request before being replaced. restart is simpler and fine for most servers.

05

Verify the Patch Applied

Confirm the running version updated and PHP-FPM is healthy:

bash 
# Check the new version number
php -v

# Confirm PHP-FPM service is running (replace 8.3 with your version)
sudo systemctl status php8.3-fpm --no-pager

Healthy output looks like this — the version number should be higher than what you saw in Step 01:
